## Root causes already confirmed by supervisor inspection (verify each, do not just assert)
1. Misaligned left insets inside one drawer/view: StyleDrawer search row px-4 (16px), count px-5 (20px), card list px-3 (12px) — three different left edges in the same panel. Same pattern elsewhere: Board column section p-2, header px-2, inner scroll px-0.5; Elements grid container with only pr-1 and no left padding.
2. Selection rings are drawn OUTSIDE the card (Tailwind ring-1/ring-2 is a box-shadow outside the border box) and are clipped by overflow-hidden / overflow-y-auto ancestors: BaseDrawer outer overflow-hidden, Board inner scroll px-0.5, Elements grid overflow-y-auto with no left padding, ElementDetail state cards ring-2 inside overflow-y-auto, Copilot/ElementDetail asides overflow-hidden, BaseCard overflow-hidden.
3. Shadows (shadow-ios, shadow-ios-pill, shadow-ios-lg on hover) extend beyond a card and are clipped by the same overflow containers when the container padding is smaller than the shadow spread.
4. Drawer flush mode: KnowledgeDrawer, ModelDrawer, StyleDrawer use BaseDrawer flush, so the 20px .app-drawer-body padding is removed and only the drawer's own px-3/px-4 remains.

## Fix rules (apply everywhere, not just the reported drawer)
5. One left inset per panel: within a single drawer or view, the header/search row, count/label row, and card list MUST share the same horizontal padding token. Drawer body: 20px (px-5). Main studio views: 16px (px-4). Do not leave px-3 vs px-4 vs px-5 mixed in the same panel.
6. Rings must never be clipped: change every card selection ring (ChapterCard, ElementsView element cards, ElementDetail state cards, StyleDrawer/KnowledgeDrawer/ModelDrawer cards, Copilot/Proposal cards, CommandMenu selected row, any other ring-1/ring-2 on a card) to ring-inset, OR replace the ring with an inset border of the same visual weight. After the change, grep must show zero non-inset ring-1/ring-2 on cards in src/components/studio, src/components/layout, src/components/character.
7. Scroll containers: every overflow-y-auto / overflow-x-auto container that contains a card with ring/shadow MUST have horizontal padding >= 16px and vertical padding >= 12px at top and bottom (so the first and last card's ring/shadow is not clipped), unless the ring is already inset per rule 6 — in that case padding >= 12px is acceptable, but it must be stated per container in the report. Specifically fix at minimum: BoardView column inner scroll (currently px-0.5), ElementsView grid container (currently only pr-1, no left padding), StyleDrawer/KnowledgeDrawer/ModelDrawer/SettingsDrawer card lists (currently px-3), ElementDetail scroll (px-4, check top/bottom), CopilotDrawer list (px-4, check), CommandMenu list (px-2), StudioOutline list, Manuscript selection toolbar positioning (must not be clipped by the overflow-hidden manuscript shell).
8. Shadows: where a shadow is still clipped after rules 6-7, either increase the container padding to cover the shadow spread or move the shadow inside (use a border + inner shadow instead). Do not remove shadows globally; keep the iOS look, just make it fully visible.
9. Audit list: produce a table in the final report of every container you changed, with before -> after padding, ring type, and the view/drawer it belongs to. Any container you inspected and deliberately left unchanged must be listed with a reason (e.g. "already px-5 + ring-inset, verified in screenshot").
10. No function removed, no new text inputs except the already-allowed exceptions, no explanatory small text added, no colour/palette change (keep the Phase 2 iOS system), no layout regression: Board columns, Elements grid, Manuscript writing area, Story bible full width, and drawer width (max 480px) must all stay as in Phase 2.
