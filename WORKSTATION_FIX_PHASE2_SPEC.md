## Section 1 — Screenshot UI errors to fix (evidence: screenshots in /tmp/*.png from the Phase 1 smoke run, seeded dummy project "The Salt Archive")
1. Board view navigation inconsistency: the Corkboard screenshot has no top segmented navigation (Corkboard/Manuscript/Story bible/Elements), while the other three studio views do. The left icon rail must NOT be the only way to jump views. Unify the shell: every studio view shows the same top segmented control + Story settings + Copilot capsule. Remove the duplicate unlabeled icon rail if it duplicates the segmented control, or give it labels; do not keep two different navigation systems.
2. Wasted vertical space / top misalignment: Corkboard, Elements and Manuscript all start far below the top of the main area, leaving a large empty white band, and the content below the cards is mostly empty. Top-align all studio content to the same baseline, remove the empty header container that pushes content down, and let the writing surface / card grid fill the available height in a deliberate way (Manuscript body area must be a real writing area, not a short text floating in a huge empty card; Story bible card must size to its content with a sane max, not a fixed tall empty card).
3. Story bible centred narrow card: the Story bible card is centred at ~60% width with large side margins, i.e. the old max-w-3xl pattern returning. Use the full main-area width like Manuscript/Elements, with the same padding system as the other views.
4. Writing styles drawer — duplicated title and wrong count: drawer title "Writing styles" is immediately followed by an inner page title "Writing Styles", and the header says "0 writing styles" while a Default (No Reference) built-in card is shown below. Fix the count/label logic: built-in defaults must be counted and labelled as built-in, custom styles counted separately (e.g. "0 custom styles" if that is what is meant), never a total that contradicts the visible cards. Remove the duplicate title.
5. Writing styles drawer — duplicate action and explanatory copy: "Create Style" appears twice (top-right and bottom-centre). Keep exactly one primary Create action per view. Remove the explanatory paragraphs ("The AI will infer...", "Create a writing style guide...") — they violate the no-explanatory-small-text rule. The Default card must be a capsule row, not a paragraph.
6. Drawer width: the styles drawer covers ~70% of the screen and blurs the project list behind it. Drawers must be real drawers: max ~480px, full-height, rounded left corners, background content dimmed but not duplicated inside the drawer.
7. Element status capsules are not kind-specific: the character detail panel offers Active/Changed/Planted/Advanced/Paid/Resolved. Planted/Paid/Resolved are thread statuses, not character statuses. Define a per-kind valid status map (character / event / thread / location / object) in one place, use it for both the detail panel and the Elements cards, and never offer an invalid status as selectable. Existing states that do not fit the map must be shown, not offered as a new selection.
8. Manuscript "In context" duplication: "The chart office" appears twice — once as an element capsule with status "active", once as a bare location pill with no status. Dedupe by element id: one capsule per element, always with its current status, never a bare duplicate.
9. Duplicate information/actions in the same view: Manuscript shows "90 words" twice (top-right and in the chapter card); Board shows "Plan next chapter" both at the bottom-left and top-right. Keep exactly one primary instance of each action/info per view; the other instance must be removed or demoted to a non-duplicated secondary entry that does not repeat the same label.
10. Primary-action hierarchy: several strong-blue capsules compete in one view (e.g. Manuscript: Continue + Changed + Write). Per view there is exactly one coloured key action; all other actions are neutral grey capsules. Fix every view to that rule.
11. Explanatory small text in the shell: remove the "Chapter timeline" label and the "Idea / Draft" legend at the bottom of the left timeline. Colour/selected state must carry the meaning; do not explain it in small text.
12. Language / i18n: the Phase 1 screenshots are all in English, but the user works in Simplified Chinese and the original app was Chinese. Verify the zh UI renders with the same layout: set the seeded smoke project and the UI language to zh, check for overflow/truncation of Chinese labels in capsules, segmented controls and drawers, and fix any breakage. Final screenshots for supervisor review MUST be in zh. Ensure the language setting persists (do not hard-code English).
